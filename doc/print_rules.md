# 打印文本规则说明

本文档梳理 btprint-sdk 的文本打印规则，重点说明**文本太长时的换行处理行为**。
规则来源：`BtPrintManager`（组包）+ 打印机固件（自动换行）。

## 1. 编码与字符宽度

- 所有文本以 **GBK** 编码发送（`CHARSET_GBK`）。
- 字符宽度计算规则：**ASCII 字符宽 1，其余字符宽 2**（按码点 `> 127` 判断）。
  - 英文/数字/半角符号：宽 1，GBK 占 1 字节
  - 汉字/全角符号：宽 2，GBK 占 2 字节
  - 扩展拉丁字符（如 `é`）：GBK 中也是 2 字节，宽 2，一致
- 编码替换坑：emoji、生僻字等 **GBK 无法表示的字符会被替换为 `?`**（1 字节），
  但宽度计算按原码点（可能算 2）——多列排版中这类字符可能造成 ±1 列的偏差。

## 2. 纸张与行宽

SDK 内置两种纸宽（`BtPrintManager.PaperWidth`，可用 `setPaperWidth` 切换并持久化）：

| 纸张 | 每行字符数（标准字号） | 每行打印点数 | 适用 |
|---|---|---|---|
| MM_58（默认） | 32 | 384 | 58mm 小票机 |
| MM_80 | 48 | 576 | 80mm 小票机 |

"每行字符数"指标准字号（Font A 12×24 点）下满行能容纳的宽度单位：英文 32/48 个，
或中文 16/24 个，或混合按宽度累计。**该值只参与 SDK 侧的排版计算**
（printTwo / printThree / printDivider / printImage），printText 的行宽完全由打印机决定。

## 3. printText：换行规则（核心）

```
printText(text, fontSize, align, feedLines)
```

**SDK 不做任何拆行处理**：整段文本转成 GBK 字节流，连同对齐、字号命令和
`feedLines` 个换行符一次性写入。文本超长时的换行完全由打印机固件完成。

### 3.1 打印机自动换行行为（市场默认）

**这是市场上的默认处理方式**：Epson ESC/POS 规范规定字符打印超出可打印区域右边界时，
打印机固件自动走纸换行；主流开源库（如 DantSu/ESCPOS-ThermalPrinter-Android，仅按 `\n`
拆行、不做宽度计算）和芯烨/佳博官方 demo 也都直接发送原始字节流、不做 SDK 层拆行，
与本 SDK 的 printText 一致。

固件自动换行的具体表现：

- 打印机按打印头位置**逐字符累计宽度**，到达右边界时自动回车走纸换行；
- **断词不可控**：英文单词会在任意字符间断开换行（不会在空格处优雅断词）；
- 换行后**对齐方式、字号保持不变**（ESC/POS 这些是状态型命令，持续生效直到被改写）；
- 换行点是否拆分宽字符**因机而异**：按 Epson 规范倍宽字符应整体移到下一行，
  但部分低端国产机在边界处会把一个汉字的两个字节拆到两行，打出半个字（空白块/乱码）。

如果业务需要精确的版面（绝不允许拆字、要求按词断行、折行后特殊对齐），
市场的做法是**在 SDK 层自己按宽度拆行**，再逐行发送——商用收银/外卖 SDK 普遍如此。
本 SDK 目前把这件事留给固件，需要时可再加宽度拆行工具。

### 3.2 手动换行与空行

- 文本中嵌入 `\n`：GBK 编码后就是 `0x0A`（LF），强制换行——这是控制长文本版面的唯一手段；
- `feedLines`（默认 1）：文本末尾追加 N 个空行；传 0 则不额外走纸；
- 常用技巧：空文本 + `feedLines = n` 即打 n 个空行（`PrintUtils.printEmptyLines` 的实现）。

### 3.3 字号对行宽的影响

printText 发送的字号命令与实际行宽的关系（**列数为 Epson 标称值，实际因机型/固件有偏差**）：

| fontSize | 发送的命令 | 58mm 行宽 | 80mm 行宽 | SDK 多列排版按 |
|---|---|---|---|---|
| SMALL | `ESC ! 0x01` + `ESC M 0`（Font B，9×17 点） | 约 42 列 | 约 64 列 | 32 / 48（保守，偏小） |
| NORMAL | `ESC ! 0x00` + `ESC M 0`（Font A，12×24 点） | 32 列 | 48 列 | 32 / 48（精确） |
| LARGE | `ESC ! 0x33` + `ESC M 0` | 见下方说明 | 见下方说明 | 32 / 48 ÷ 2（按 ×2 倍宽假设） |

要点：

- **SMALL 字号下行宽变大**（Font B 更窄），一行能塞更多字符；SDK 多列排版仍按标准行宽计算，
  属保守估计，不会错位，只是列间距比理论最大窄；
- **LARGE 字节的放大倍数存在两派解释**：按 Epson 规范 `ESC ! n` 的高低半字节取值 +1 为
  放大倍数，`0x33` = **×4** 宽高；而大量国产机型/教程把 `0x11` 视为"倍宽倍高"（×2），
  对 `0x33` 的实现也参差不齐（×2 或 ×4 都有）。SDK 的多列排版按 ÷2（×2 假设）计算：
  若你的机型按 ×4 放大，大字体多列会触发超宽兜底（text2 掉行），属预期内的机型差异；
- 超长的大字文本折行后对齐方式保持，行数随放大倍数增加。

### 3.4 各类打印内容的超宽默认处理（市场惯例）

| 内容类型 | 超宽时的市场默认行为 | 本 SDK 的处理 |
|---|---|---|
| 字符文本（printText） | 固件自动换行（见 3.1），不断词、低端机可能拆字 | 不干预，交给固件 |
| 两列/三列（printTwo/Three） | 商用 SDK 普遍在 SDK 层排版+超宽兜底 | 两种模式可选：默认超宽列掉到下一行；`setColumnWrapEnabled(true)` 后表格模式（列内折行、多列超行均分空间） |
| 位图（GS v 0，printImage） | **不换行，超出部分直接裁掉**（右侧空白） | 宽度钳制在纸宽内并按 8 点取整，正常不会超 |
| 一维条码（printBarCode） | 超宽**打印失败或乱码**，固件不处理 | 不校验长度，由调用方控制内容长度与 width |
| 二维码（printQrCode） | 按模块数自然扩展，超宽右侧被裁 | 不校验，由调用方控制内容长度与 size |

结论：**"超宽"在字符模式是换行问题，在位图/条码模式是裁剪问题**——只有文本类会自动换行，
图形类没有任何换行概念，超出即丢失。

### 3.5 超长文本示例

58mm 机器、NORMAL 字号、左对齐，打印 40 个汉字（宽 80，超出 32）：

```
SDK 发送：  [ESC a 0][ESC ! 0][ESC M 0] + 80 字节 GBK + [0A]
打印机输出：第 1 行 16 个汉字（32 宽度单位，到边界自动换行）
            第 2 行 16 个汉字
            第 3 行 8 个汉字 + 走纸 1 行（feedLines=1）
```

## 4. printTwo：两列排版的超宽规则

```
printTwo(text1, text2, fontSize)
```

两种模式，由全局配置 `PrintUtils.setColumnWrapEnabled(...)` 切换（默认 `false`）。

### 4.1 默认模式（columnWrapEnabled = false）

1. 按第 2 节规则算出行宽 `totalWidth`（LARGE 字号减半）；
2. 计算 `w1 = 宽(text1)`、`w2 = 宽(text2)`：
   - **放得下**（`w1 + w2 ≤ totalWidth`）：单行输出，中间补 `totalWidth - w1 - w2` 个空格（右列推到行尾）；
   - **放不下**：**不截断**，自动改为两行——`text1` 一行，`text2` 下一行（均左对齐）。

### 4.2 表格模式（columnWrapEnabled = true）

放得下（判定条件 `w1 + 1 + w2 ≤ totalWidth`，列间至少留 1 个空格，比默认模式严格：
恰好铺满 `w1 + w2 = totalWidth` 时默认模式输出单行、表格模式会折行）时与默认模式一致；
超宽时**列内折行**，规则：

- **仅左列超宽**：左列折行，右列留在第一行。左列折行宽度 = `totalWidth - 间距 - w2`
  （即第一折宽度），后续每折不超过它；
- **仅右列超宽**：右列折行且**逐行靠右**（右边界对齐行尾），左列留在第一行；
- **两列都超宽**：**均分空间**（各 `(totalWidth - 间距) / 2`），左列左对齐、右列右对齐
  各自折行，总行数取两列折数最大值——像表格一样显示；
- 任意位置硬折行（不断英文单词），列间至少留 1 个空格。

例（58mm、NORMAL、W=32）`printTwo("整单八五折会员专享优惠活动", "100.00")`：

```
整单八五折会员专享优 100.00      ← 左列预算 25，右列留第一行
惠活动
```

两列都超宽时（各 15 列）：

```
商品名称特别特别长的  100.00
商品               200.00
                  小计 800.00   ← 右列折完且靠右
```

## 5. printThree：三列排版的超宽规则

```
printThree(text1, text2, text3, fontSize)
```

### 5.1 默认模式（columnWrapEnabled = false）

1. 行宽换算同 printTwo；`rem = totalWidth - w1 - w2 - w3`；
2. **`rem < 0`（总宽超行）**：`text1` 独占一行，剩余空间按 `w2 + w3` 重新计算，
   `text2`、`text3` 排在第二行——中右列不会在单行里硬塞；
3. 未超宽时：按"左列是否短于半行"分两种空格分配策略，把 `text2` 尽量推到行中、
   `text3` 推到行尾；
4. 全部输出左对齐（显式发送 `ESC a 0`，不继承外部对齐状态）。

### 5.2 表格模式（columnWrapEnabled = true）

放得下时沿用默认模式的单行排布；超宽时**列内折行**，规则：

- **仅一列超宽**：该列在预算宽度内折行——左列折行留第一行给中右列、
  中列折行且**居中**、右列折行且**靠右**；其余列留在第一行；
- **多列都超行**：**均分三份空间**，左列左对齐 / 中列居中 / 右列右对齐各自折行，
  总行数取三列折数最大值；
- 折行宽度 = 该列第一折宽度，后续每折不超过它；任意位置硬折行；列间至少留 1 空格。

## 6. 分割线与标题

```
printDivider(char, length)   // 默认 "-"，length=-1 时铺满当前纸宽
printTitle(text, ...)        // 分割线 + 大字体居中文本 + 分割线
```

- 分割线是 `char × N` + 换行，**强制居中**，结束后恢复左对齐；
- `char` 为宽字符（如 `＝`）时按宽 2 折算个数，保证铺满整行；
- `length > 0` 时按指定字符数输出，可打出短分割线。

## 7. 打印后的状态残留

各方法执行完毕后打印机的状态（影响后续任务的呈现）：

| 方法 | 对齐 | 字号 |
|---|---|---|
| printText | 保持本次设置的 align | 保持本次设置的 fontSize |
| printTwo / printThree | 恢复左对齐 | 保持本次设置的 fontSize |
| printDivider | 恢复左对齐 | 不变 |
| printQrCode / printBarCode / printImage | 恢复左对齐 | 不变（码图尺寸与字号无关） |
| cutPaper / openCashDrawer | 不变 | 不变 |

即：**对齐是每次排版方法自管的，跨任务不会错位；字号是持续状态**，
大字号打印后记得在下一次 printText 时通过 fontSize 指定字号（`setFont` 已废弃，
其字号/粗体残留会污染后续打印）。

## 8. 常见坑速查

| 现象 | 原因 | 对策 |
|---|---|---|
| 长文本折行位置不符合预期 | 换行由打印机固件按点宽决定 | 文本内自行插入 `\n` 控版 |
| 英文单词被从中间折断 | 固件自动换行在任意字符处断开，不按词断 | 自行断词 + `\n` |
| 行尾汉字变成半个字/空白块 | 低端机型固件把双字节字符拆到两行 | 缩短该行文本，或自行插入 `\n` 避开边界 |
| 中文变成 `?` | GBK 无此字符（emoji/生僻字） | 文本过滤或改用图片打印 |
| 大字体排版超宽 | 机型对 `ESC ! 0x33` 放大倍数解释不同（×2/×4） | 缩短文本或降字号；多列超宽会兜底换行不丢内容 |
| 图片/条码右侧打不出来 | 图形类超宽是裁剪不是换行 | 降低图片宽度/条码宽度参数 |
| 两列对不齐 | 文本含 GBK 不可编码字符 | 过滤非常规字符 |
| 打完标题后正文也变大 | 字号是持续状态 | 后续 printText 显式传 fontSize |
